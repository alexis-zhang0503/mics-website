# 智能通信研究方向页面设计

日期：2026-09-02
状态：待用户审阅
涉及页面：`research-communication.html`、`en/research-communication.html`

## 1. 目标

将当前占位页面改造成与“多模态感知”详情页结构和视觉语言一致的完整研究方向页面。页面必须以通信问题为主轴，同时真实呈现人工智能、Agent、世界模型、具身智能与语音认知筛查之间的关系。

页面的核心判断是：

> 以通信与信号处理为研究对象，以 AI、Agent 和世界模型为核心方法，以网络自治、具身边缘系统和智能健康为验证场景。

页面不把热点词并列罗列，而是从信号、网络到系统形成一条连续研究链：

```text
通信、感知与声学信号
        ↓
智能信号处理与可信状态构建
        ↓
无线世界模型与网络智能体
        ↓
任务驱动通信、边缘协同与安全行动
        ↓
网络、具身和健康场景中的真实反馈
```

## 2. 页面定位

中文主标题保持“智能通信”，避免改变首页既有研究方向命名。

中文副标题：

> 面向 AI 原生网络与具身智能的信号处理、世界建模和可信智能体

英文主标题保持 `Intelligent Communication`。

英文副标题：

> Intelligent signal processing, world modeling, and trustworthy agents for AI-native networks and embodied systems

页面开场需要明确两类互补目标：

1. AI for Communication：利用 AI 理解、预测和自主控制通信系统。
2. Communication for AI：设计支撑多智能体、具身系统和边缘智能的通信机制。

“可信闭环”贯穿两者，包括证据追踪、执行前验证、因果诊断、局部修复和安全回退。

## 3. 内容结构

### 3.1 Hero

保留现有负责人姓名、邮箱、返回链接和 `Research Direction 03`。更新页面描述信息，但不改变站点导航。

### 3.2 研究命题

使用与多模态感知页一致的 `news-article`、`news-header` 和 `news-summary` 结构。

建议中文标题：

> 从智能信号到可信行动的 AI 原生通信

核心介绍应回答：

- 为什么通信网络需要从被动传输系统发展为可感知、预测和行动的智能系统；
- 为什么真实网络中的观测过期、状态冲突、资源约束和执行风险不能只靠通用大模型解决；
- 为什么通信系统既是 AI 的研究对象，也是分布式智能和具身系统的基础设施。

摘要框只陈述已经由用户确认的研究范围，不承诺未完成结果。

### 3.3 研究背景

背景部分围绕以下逻辑展开：

1. 6G、智能物联、车联网和低空网络使通信系统与感知、计算和控制深度耦合。
2. 传统优化通常依赖静态模型和单次决策，难以处理持续变化的网络状态。
3. Agent 可以连接业务意图、网络遥测、分析工具和配置接口，但真实执行必须有验证、追踪和恢复机制。
4. 具身智能和多智能体系统进一步要求通信优化面向任务成功率，而不仅是吞吐量。

不在页面中使用“行业领先”“国际先进”等无法验证的评价性措辞。

### 3.4 三个研究层次

复用多模态感知页的 `focus-list` 和 `focus-item` 结构。

#### 01 智能信号处理与多模态健康

研究对象包括无线信道、WiFi CSI/BFI、毫米波雷达、语音和生理时序信号。重点研究信号增强、时频建模、表征学习、多模态融合、跨设备和跨人群泛化、不确定性估计，以及端边协同处理。

语音需要被准确描述为“声学信号”，不能称为无线信号。AD 语音筛查作为智能信号处理的健康应用，重点放在跨语料、跨语言、跨任务和跨采集协议的泛化问题。若进一步涉及原始语音或任务特征的端边传输、联邦学习和隐私保护，可自然进入智能通信系统研究。

#### 02 无线世界模型与网络智能体

研究如何从信道、流量、拓扑、用户移动、业务需求和网络遥测中构建动态网络状态，预测环境演化及候选操作的影响，并支持 Agent 完成网络分析、规划、工具调用、资源控制和故障恢复。

世界模型必须限定为“正在推进的研究议程”，不能暗示已有成熟统一模型。网络智能体部分可由用户现有的无线网络 Agent、验证引导协调和轨迹保障工作支撑。

#### 03 具身与边缘智能通信

研究机器人、无人机、智能汽车和智能空间中的通信、感知、计算与行动协同。重点关注任务驱动的信息传输、多智能体状态与意图交换、端边云协同推理、网络中断下的安全退化，以及时延、带宽、能耗与任务成功率的联合优化。

此方向承担 `Communication for AI` 的主要内容，避免把具身智能写成与通信无关的机器人算法。

### 3.5 可信通信智能闭环

增加独立章节，使用简洁文字和编号步骤解释：

1. 感知：采集通信、环境和任务信号。
2. 建模：形成带来源和不确定性的动态状态。
3. 预测：利用世界模型评估候选行动后果。
4. 协同：Agent 与网络节点交换必要的状态、意图和证据。
5. 验证与执行：检查约束，执行动作，必要时修复或回退。
6. 反馈：根据真实结果更新状态和模型。

该章节是页面叙事中心，用于统一三个研究层次。

### 3.6 代表性工作

只展示已经公开或由用户明确授权公开的信息。默认按“与通信主线的直接程度”排序，不按论文时间或个人偏好排序。

优先候选：

1. `WirelessOpsAgent: A Benchmark and Agent Design for Action Assurance in Wireless Networks`：网络智能体与安全执行的直接支撑。
2. `Fluid Antenna-Aided ISAC for Urban Drone Delivery: System Design, Edge Realization, and Evaluation`：通信、感知、低空系统和边缘实现的直接支撑。
3. `Secrecy Rate Maximization for Fluid Antenna-aided ISAC System with UAVs`：无线通信、ISAC 与 UAV 场景支撑。
4. `ContractSkill: Repairable Contract-Based Skills for Multimodal Web Agents`：作为可验证、可修复 Agent 能力的方法基础。
5. `VITAL-RAG: Invariance Race for Context Allocation in Coding Agents`：作为有限上下文中的证据选择和 Agent 状态构建方法基础。

语音 AD 和 SuperSenseDoctor 暂作为“在研主题”写入研究内容，不默认列入公开代表作，也不公开本地稿件中的未发表数值。待用户确认公开状态后再增加论文条目。

不将 GUI、OCR 或其他弱通信关联工作放入本页代表作。纯通信优化成果可以展示，但应说明它们支撑的是通信系统层，而不是强行包装为 Agent 或世界模型。

### 3.7 未来方向

未来方向保持克制，限定为：

- 面向动态无线环境的世界模型和数字孪生；
- 可验证、可恢复的网络智能体；
- 多智能体和具身系统的任务驱动通信；
- 声学与无线多模态健康信号的端边协同处理；
- 面向真实设备和网络约束的低时延部署。

不写具体招新要求、团队名单或合作项目，因为用户尚未确认这些信息。现有占位式 Team 和 Opportunities 区块将被完整研究内容替换，而不是填入虚构资料。

## 5. 视觉与实现约束

- 复用 `research-multimodal.html` 已有的详情页布局类，不引入前端框架或构建系统。
- 优先只修改两个通信详情页；仅在已有样式无法承载内容时，对 `css/style.css` 做小范围复用式补充。
- 不增加来源不明的图片。第一版可以完全依赖排版、编号和现有视觉组件。
- 保持语义化标题层级、键盘访问、移动端导航和相对路径。
- 不改变首页默认语言逻辑、其他研究方向页面或成员信息。

## 6. 验证标准

实施完成后必须验证：

1. 中文和英文页面不再包含占位文字。
2. 中英文章节、论文数量和链接一致。
3. 所有站内相对链接和资源存在。
4. 页面通过本地 HTTP 服务访问，无控制台资源错误。
5. 桌面端和移动端无横向溢出，长英文标题能够换行。
6. HTML 标题层级连续，图片如有使用则包含有效 `alt`。
7. Git diff 只包含设计批准范围内的文件。
8. 未公开稿件的实验数值、匿名信息和本地路径不会进入网页。

- 不宣称已有统一世界模型、具身平台或临床部署结果。
